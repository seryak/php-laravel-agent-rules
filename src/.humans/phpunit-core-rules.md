# phpunit/core rules

## PHPUnit Core

- В этом приложении для тестирования используется PHPUnit. Все тесты должны быть написаны в виде классов PHPUnit.  
  Для создания нового теста использовать `php artisan make:test --phpunit {name}`.
- Если в проекте встречается тест, написанный с использованием **Pest**, его необходимо преобразовать в PHPUnit.
- Каждый раз после изменения теста необходимо запускать **только этот конкретный тест**.
- Когда тесты, относящиеся к реализуемой функциональности, проходят успешно, следует спросить пользователя, нужно ли дополнительно запустить **весь тестовый набор**, чтобы убедиться, что всё по‑прежнему работает корректно.
- Тесты должны покрывать:
  - успешные сценарии (happy paths),
  - сценарии с ошибками (failure paths),
  - нестандартные и пограничные случаи (weird paths).
- Запрещено удалять любые тесты или файлы тестов из директории `tests` без явного одобрения.  
  Это не временные и не вспомогательные файлы — они являются **ключевой частью приложения**.

## Запуск тестов

- Перед финализацией изменений запускать **минимально необходимое количество тестов**, используя подходящий фильтр.
- Для запуска всех тестов:
  ```bash
  php artisan test
  ```
- Для запуска всех тестов в одном файле:
  ```bash
  php artisan test tests/Feature/ExampleTest.php
  ```
- Для фильтрации по имени конкретного теста (рекомендуется после изменения связанного кода):
  ```bash
  php artisan test --filter=testName
  ```
